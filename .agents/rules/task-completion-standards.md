# 任务完成与验收强制标准

> **Scope (Globs)**: `["docs/00-7待办/**/*", "docs/02-规划/**/*"]`

## 1. 任务完成准入门槛（闭环与凭据）

任务标记为“已完成”前，必须同时满足以下条件：

1. **终局闭环保证（严禁半途退出）**: 智能体必须在当前回合中自主攻坚推进至彻底闭环，严禁向用户抛出中间半成品代码并草率结束回合，严禁将智能体自身应排查与执行的步骤推卸给用户（如“请您自行执行迁移并排查报错”）。
2. **铁证防主观幻觉（物理凭证）**: 陈述“已修复/已通过/已完成”必须附带终端真实命令输出（退出码为 0）、环境日志检查结果或实际代码行，**严禁在未真实运行命令或未检查日志的情况下凭空脑补“已全部正常”**。
3. **环境日志无新增报错 (强制)**: 必须检查相对工作区根目录 `tilo-backend-app/backend/logs/{APP_ENV}_{BACKEND_PORT}/error.log`（或核心引擎 `tilo-core-engine/logs/...`），并结合同目录 `info.log` 与 Nginx `/var/log/nginx/error.log` 排查，确认无未捕获异常、Python Traceback 或 500/502 错误。`APP_ENV` 与 `BACKEND_PORT` 以被检查服务的运行配置为准。
4. **无关键 TODO 残留**: 代码中若存在标注核心未完成逻辑的 TODO 注释，不得标记为已完成。
5. **Mock/存根透明透明**: 任何仍在使用 mock 或占位实现的功能，必须在待办清单中明确标注 `[Mock]`，严禁在 API 调用失败时静默降级为假数据糊弄用户。
6. **任务归档与目录物理流转 (SSOT - 模式 A)**:
   - 任务验收闭环后，原始方案与脚手架不做物理删除，统一由活跃专案目录（主仓 `docs/00-7待办/04-混合/<专案>/` 或子仓 `<subrepo>/docs/00-待办/<专案>/`）完整移动至对应仓的 `已完成/<专案>/` 目录保留复盘底稿，未来由人工定期手动批量清理。物理目录位置即状态，无需额外维护中心化总待办清单文件。
7. **用户 Review 优先与提交解耦 (强制)**:
   - 任务在技术层面的“闭环完成”严格限定于本地代码变更与质量验证（通过类型检查、自动化测试、日志无新增报错）。
   - **严禁未经用户明确指示私自自动 `git commit` 或 `git push`**。
   - 完成任务时，智能体必须呈报清晰的修改点与验证凭据，将变更严格保留在本地工作区等待用户 Review 确认。日常答复不主动输出建议 Commit 信息，仅在用户明确要求起草或发出提交指令时按 Conventional Commits 规范提供。
8. **需求规格 (spec.md) 防臆造与代码现实对齐门禁 (Spec-Realism Gate)**:
   - 编写或更新需求规格（spec.md）前，**必须先做真实代码基线探测**：严禁凭直觉脑补现有界面交互与组件入口（例如将模式切换开关臆想为全选入口）；
   - 规格中的交互文案、按钮加载态、语义样式必须与现有系统完全对齐（禁用原始色相，统一用语义 Token；按钮 loading 文案必须与 JSX 严格一致）；
   - 代码实现若发生调整（如将文案由 `正在打包...` 调整为 `打包中`），必须反向同步更新 `spec.md`，严禁让规格与实现产生长久未对齐的“两张皮”状态。

## 2. 状态分档标记

无法一次性闭环的任务，必须采用分档标记，严禁笼统标注为已完成：

| 标记 | 含义与判定标准 | 示例 |
|------|--------------|------|
| **UI 完成** | 界面可交互，数据为 mock/stub | `创建案件弹窗 - UI 完成（创建接口未对接）` |
| **联调完成** | 前端连通后端真实接口，数据库读写与错误处理跑通 | `驾驶舱数据展示 - 联调完成` |
| **闭环完成** | 全链路真实逻辑跑通，输出真实业务结果并通过测试 | `行动卡执行 - 闭环完成` |

> 达到“闭环完成”后，将专案目录完整移动至 `docs/00-7待办/已完成/` 目录。

## 3. 前后端联调验收要求

联调类任务必须满足：
1. **真实网络与数据**: 前端实际发出 HTTP 请求，后端返回真实数据库查询数据，非拦截器伪造。
2. **异常与权限覆盖**: 前端完整处理 4xx/5xx 与网络超时，鉴权与案件隔离校验通过。
3. **物理凭证**: 附带 Swagger 调用、curl 输出、浏览器 Network 截图、或自动化测试（pytest / Playwright）通过结果之一。
