# 沟通协作与记事编写 (Docs Writer)

## 何时使用

- 需要将群聊记录、讨论内容转化为结构化纪要
- 会议记录需要提炼共识和行动项
- 个人记事需要逻辑化整理

## 核心框架：CCDA

无论处理何种文档，必须按以下四维度重组信息：

### A. 背景与目标
- 因何而起：触发本次记录的背景
- 预期目标：希望达成什么目的

### B. 核心内容与事实
- 干货提炼：过滤情绪化、重复信息，保留核心观点与论据
- 逻辑分层：使用层级列表展示演进或维度
- 关键变量：时间、地点、涉及人物或系统状态

### C. 决策与共识
- 定论是什么：明确的结论或共识
- 分歧点：未达成一致的部分必须记录

### D. 行动项
- TODO 闭环：明确的负责人、时间和交付物
- 后续跟进：外部依赖或待观察事项的触发点

## 语言风格准则

- 高密度表达：剔除废话，使用短句直戳要害
- 专业中立：保持客观，不带个人情绪
- 实战导向：重点描述"这在执行中意味着什么"
- 适度总结：不得过度精简导致背景缺失
- 透明度：不确定信息标注"待核实"

## 代码定位与结构探索规范

在执行本技能的代码查找与依赖分析时，请遵守以下优先级与防呆规则：

1. **优先使用 CodeGraph（当 `.codegraph/` 目录存在时）**：
   - **防陈旧索引**：使用前必须先在终端执行 `codegraph sync`，确保索引数据库反映最新代码变动。
   - **三大场景运用**：
     - **场景 1（跨层链路追溯）**：使用命令行 `codegraph explore "<符号名/问题>"` 批量获取源码及跨层调用关系链（Call Chain）。
     - **场景 2（全库调用点审计/影响面分析）**：使用命令行 `codegraph node <函数/类/组件名>` 检查其 callers，确保影响面审计零遗漏。
     - **场景 3（架构与符号定位）**：使用命令行 `codegraph explore "<数据结构/接口名>"` 快速定位全局符号定义。
   - **真实性校验**：通过 CodeGraph 定位到具体文件位置后，**必须使用文件查看工具读取最新真实源码内容**，严禁直接无条件盲信索引快照。

2. **降级兜底（当未建立 CodeGraph 索引时）**：
   - 使用 `grep` / `find` 或开发工具进行标准文本匹配。

## 执行步骤

1. **素材输入**：识别场景（会议/讨论/记事），提取关键词
2. **结构建模**：套用 CCDA 框架，检查逻辑闭环
3. **文档输出**：按场景选用对应格式
4. **自检**：检查行动项是否具备负责人和截止时间，核心定论是否清晰

## 输入参数

| 参数名 | 类型 | 默认值 | 描述 |
| :--- | :--- | :--- | :--- |
| `material` | `string` | - | 原始素材文本 |
| `scene` | `string` | `discussion` | 场景：meeting / discussion / personal |
| `title` | `string` | - | 文档标题 |
