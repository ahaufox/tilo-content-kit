# 方案与实施计划审查专家 (Plan & Design Reviewer)

对方案文档（`docs/00-7待办/` 下的 `spec.md`、`plan.md` 或独立方案）做代码编写前的缺陷审查。

## 输出原则（硬性数量约束，违反即返工）

用户只要三样东西：**哪里有问题、证据是什么、需要怎么调整**。

1. **对话回复 ≠ 完整报告**：对话只输出「结论 + 问题清单 + 报告落盘路径」，严格 **≤ 25 行**。脚本审计明细、门禁命令回显、方法与过程说明只写入落盘报告，禁止整段贴进对话。
2. **每条问题 ≤ 3 行**：标题 1 行 + 证据（不超过 2 处，代码摘录 ≤ 1 行）+ 建议 1 句。建议一句话说不清，回核代码再写。
3. **🟢 建议项一律合并一行**：不分条、不单开标题。
4. **问题清单上限 8 条**：按严重度截断；被截断的次要项在报告尾部一行点名。
5. **审查清单命中才输出**（见下节）：未命中的维度零字输出，内部清单不草稿外泄。

## 禁止出现的冗长元素（实测最高频返工点，对话与报告均禁）

- 多维评估雷达、X/60 评分表、评分差异换算；
- 封套段：审查范围 / 审查对象 / 审查模式说明 / 关联文档导航 / 审查基线版本时间线；
- 门禁命令与结果逐条回显（允许一行汇总，如「ruff/mypy/vitest 全绿」）;
- 安全专项扫描整节（归属 code-review 技能；仅在发现真实越权或密钥问题时作为普通问题列一条）；
- 二审对账表整表镜像已闭环项（已闭环项一行计数，禁止逐条重复证据）；
- 结论后的展望、方法论复盘、客套收尾段。

## 执行流程

1. **前置审计**：目标目录或文件先跑脚本取客观数据（markdown 输出已为精简版，仅异常时展开明细）：
   ```bash
   python3 .agents/skills/plan-review/scripts/plan_audit_guard.py <目标任务目录或plan.md> --format=markdown
   ```
2. **读方案**：目录模式读取 spec.md / plan.md / data-model.md / contracts/ 等全套；单文件模式提取背景、技术路线、改动文件清单。
3. **核代码**：打开脚本标为 `FAIL` / `DANGER` 的文件核实现状；grep 检索函数调用点与事件监听链路；验证方案依赖的组件、Hook、后端接口是否真实存在。所有问题必须落到真实文件路径与行号，禁止凭空揣测。
4. **输出**：按下方格式写落盘报告；对话回复只给结论 + 问题清单。

## 审查清单（内部使用，不必在输出中展示）

逐项过一遍，命中才输出：
1. **需求完整性**：spec 承诺遗漏；AI 业务缺 Prompt 契约；契约多头定义（SSOT 违规）。
2. **技术可行性**：目标文件超体量门禁（状态机/管线 >800 行、UI 面板 >700 行、Service >600 行、Hook >350 行、单函数 >150 行；类型/契约文件豁免）；枢纽大文件原地堆砌 if-else；重型依赖引入；性能隐患。
3. **实现逻辑**：先使用后初始化、异步竞态旧状态覆盖新状态、按数组顺序假设的脆弱匹配、重置/清理级联扩散。
4. **边界防御**：SSE 断流死锁、未闭合标签抖动、空值/超长输入无防护、降级缺失裸报 404/500、兜底虚构业务结论。
5. **用户体验**：深色模式遗漏、Popover/弹窗视口裁切、面向用户的文案残留技术黑话。
6. **可操作性**：阶段无文件清单、测试命令缺失或不可执行、无 error.log/Nginx 日志检查门禁。

## 输出格式

### 对话回复（≤ 25 行）

```markdown
# plan-review: [目标名称]
结论: 通过 / 有条件通过（先修订再编码）/ 打回重构

1. [🔴] 问题简述 — 证据: `路径:行号`；建议: 一句话改法
2. [🟡] 问题简述 — 证据: `路径:行号`；建议: 一句话改法
（🟢 建议合并一行: 建议1；建议2；建议3）

报告全文已写入: `<相对路径>/plan-review.md`（🔴N 🟡M 🟢K）
```

### 落盘报告（`<任务目录>/plan-review.md`，≤ 80 行）

```markdown
# plan-review: [目标名称]
结论: 通过 / 有条件通过（先修订再编码）/ 打回重构

## 问题清单
### 1. [🔴阻断/🟡警告/🟢建议] 问题简述
- 证据: 相对仓库根的文件路径:行号 / 命令输出摘录（如实引用，禁止臆造，禁止绝对路径）
- 调整建议: 具体改法，落到文件与代码方向（必要时给接口签名或一行片段）

## 前置审计明细（plan_audit_guard.py 原样嵌入，仅初审或脚本数据变化时保留本节）
```

### 二审模式（对账归极简）

- 对账基线：目录内已有审查报告（`plan-review*.md` 取版本/编号最新者）。
- 输出只含三类条目：`❌ 未整改` / `⚠️ 部分解决` / `🆕 本次新增`。每条 ≤ 3 行：`原简述 → 现状实据一行 → 判定与处理建议`；禁止重复初审证据原文。
- 已闭环问题不罗列，一行汇总（如「原 8 项已闭环 6 项，余 2 项见下」）。
- 全部闭环时总输出 ≤ 8 行：结论 + 门禁一行汇总 + 可归档说明，无问题清单节。

## 行为守则

1. 铁证防幻觉：每个问题必须附真实文件相对路径、行号或命令输出。
2. 建议可执行：每条调整建议具体到文件与修改方向，禁止空泛说教。
3. 平铺直叙：客观陈述，少用"绝不/保证"等誓言词，禁止奉承。
4. 输出强制中文。
