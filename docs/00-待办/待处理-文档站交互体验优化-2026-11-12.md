# 待处理-文档站交互体验优化-2026-11-12

## 问题背景

`sdks/tilo-content-kit/demo/` 是 `@tilo-ui/content-kit` 的文档 / Demo 站（GitHub Pages 部署源，产物 `demo/dist`）。
页面内容较长，自上而下包含：Hero、能力总览、七个可交互 Demo 块
（`/markdown`、`/convert`、`/content`、`/legal`、`/tiptap`、`/collab`、`/theme`）、能力证据（Proof）、
开发接入（Start）、README 文档面板（由 SDK 自身的 `MarkdownContent` 渲染）、范围与边界（Bounds）。

当前站点仅有顶部的横向 `nav` 锚点（4 个链接），缺乏长页面下的滚动联动目录、
关键交互的即时反馈、代码复制便利性、包管理器切换与移动端窄屏适配。
本次记录围绕 5 个交互体验增强点，统一收敛在 `demo/` 内，不污染 SDK 生产出口 `src/`。

## 分析结果

### 1. 浮动目录侧边栏（Table of Contents）
- **现状**：`demo/src/App.tsx` 的 `<header className="nav">` 仅有顶部 4 个锚点（`#proof` / `#start` / `#docs` / GitHub），
  `<main>` 内 13 个 `section`（含 7 个 Demo 块）没有任何滚动联动的悬浮目录，长页面下用户易迷失当前阅读位置。
- **目标**：在右侧或左侧增加轻量悬浮 TOC，监听滚动（IntersectionObserver / scroll 节流）高亮当前所在模块，
  并提供「回到顶部」锚点；目录项与现有 `id`（`#demo`、`#convert`、`#content`、`#legal`、`#tiptap`、`#collab`、`#theme`、`#proof`、`#start`、`#docs`、Bounds 等）对齐。

### 2. 操作提示（Toast / Tooltip）
- **现状**：
  - `demo/src/components/ThemeDemo.tsx` 的「注入非法值」按钮（`applyPreset('broken')`，第 117 行）点击后仅切换 token 状态，
    拦截结果靠 `token-result` 区域静态展示，无「已触发拦截」的瞬时提示。
  - `demo/src/components/CollabDemo.tsx` 的「AI 写入一段」按钮（`aiWrite()`，第 123 行）点击后仅在右侧面板插入段落，
    无「已写入」的即时反馈气泡。
- **目标**：在这类关键交互旁加短暂高亮提示或小气泡（Toast），明确告知「已触发拦截 / 已写入」，
  提升即时反馈感；需配合 `aria-live` 做无障碍降级。

### 3. 一键复制按钮
- **现状**：`demo/src/components/CodeSample.tsx` 已为「代码参考」折叠区（`Accordion` 内）提供 `CopyButton`（复制成功变「已复制」）。
  但 `App.tsx` 第 120 行用 `MarkdownContent` 渲染的 README 文档面板（`#docs` section）内的 `pre/code` 块，
  由 `src/markdown/components.tsx`（第 23–41 行）渲染为纯 `<pre><code>`，**不带复制按钮**。
- **目标**：补齐 README 文档面板内代码块的复制能力（例如为文档面板定制带复制按钮的 `code`/`pre` 渲染，
  或在 `MarkdownContent` 的 `components` 覆盖层注入复制按钮），同时保留「本站即渲染效果样例」的 dogfooding 语义。

### 4. 多 Tab 语言 / 包管理器切换
- **现状**：`demo/src/components/StartSection.tsx` 第 12 行安装命令写死 `pnpm add @tilo-ui/content-kit@${CONTENT_KIT_VERSION}`，
  `data/snippets.ts` 中的接入片段也大概率是单一包管理器。
- **目标**：在「开发接入」及涉及安装/引入的代码参考中支持 pnpm / npm / yarn 快速切换（同一份语义，三套命令互切）。

### 5. 移动端降级
- **现状**：`demo/src/site.css` 中 `entry-grid`、`token-grid`、`start-grid`、`theme-preview` 等左右对照 / 多列网格
  在窄屏下存在水平溢出或挤压风险（如 ThemeDemo 的 token 编辑网格、StartSection 的左右分栏）。
- **目标**：为移动端 / 窄屏优化布局 —— 将左右对照的编辑器、多列网格自动堆叠为上下 Tabs 切换展示，
  避免表格与编辑器发生水平溢出；以 CSS 媒体查询 + React 自适应容器为主，不引入重依赖。

## 建议的处理方式

| 编号 | 任务 | 建议落点 | 验收标准 |
| :--- | :--- | :--- | :--- |
| T1 | 浮动 TOC + 回顶部 | 新增 `demo/src/components/Toc.tsx`，在 `App.tsx` 挂载；滚动监听高亮 `aria-current` | 滚动时目录高亮随当前 section 变化；点击目录平滑跳转；窄屏下自动隐藏或折叠 |
| T2 | 关键交互 Toast | 新增轻量 `Toast`/`useToast` 工具，挂载于 ThemeDemo「注入非法值」与 CollabDemo「AI 写入一段」 | 点击后在按钮旁出现短暂气泡「已触发拦截 / 已写入」，约 1.6s 自动消失；`aria-live` 可读 |
| T3 | README 代码块复制 | 为文档面板定制 `MarkdownContent` 的 `code`/`pre` 覆盖组件（含复制按钮） | `#docs` 面板内每个代码块右上角显示「复制」按钮，点击后提示「已复制」 |
| T4 | 包管理器 Tab 切换 | `StartSection.tsx` 包装 `InstallTabs`（pnpm/npm/yarn）并复用至 `snippets` 安装片段 | 切换 Tab 即时更新安装命令文本；默认高亮 pnpm |
| T5 | 移动端响应式 | 在 `site.css` 增加 `@media (max-width: 768px)` 断点，网格堆叠为 Tabs / 纵向 | 375px 视口下无水平滚动条；左右对照降级为上下 Tabs |

## 需要注意的点

- 文档站仅用于演示与 dogfooding，非生产 SDK；改动应约束在 `demo/` 内，不得污染 `src/` 包出口与对外 API。
- TOC（T1）与 Toast（T2）需做无障碍处理（`aria-current` / `aria-live`），并在不支持 `IntersectionObserver` 时回退为现有锚点导航。
- T3 复制按钮不应破坏「README 由 `MarkdownContent` 渲染、本站即样例」的语义；如需覆盖 `components`，应仅作用于文档面板实例，不影响其它 Demo 的 `MarkdownContent` 用法。
- T5 移动端降级优先用原生 CSS 媒体查询与 `Tabs` 组件，避免引入额外响应式框架，保持演示站轻量。
- 改动后需重新构建文档站产物（`demo/dist`），Pages 部署流程见 `.github/workflows/pages.yml`；CI 校验见 `.github/workflows/ci.yml` 与 `.cnb.yml`。
- 参考站点现状的现有源码：`App.tsx`、`ThemeDemo.tsx`、`CollabDemo.tsx`、`StartSection.tsx`、`CodeSample.tsx`、`src/markdown/components.tsx`、`demo/src/site.css`。
